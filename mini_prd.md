# PRD: Telegram-бот учёта инспекций — версия 2

## 1. Назначение

Бот собирает данные по инспекциям от экспертов и специалистов, автоматически определяет поставщика по общему файлу сверки, хранит историю исправлений и формирует Excel-выгрузку с раздельными вкладками по видам работы.

## 2. Роли

- **Администратор** управляет пользователями, может назначать новых администраторов, загружает файл сверки, просматривает и исправляет записи любого сотрудника, формирует полные и инкрементальные выгрузки.
- **Эксперт** работает по проектным сценариям, исправляет собственные записи за любые месяцы и выгружает только свои данные.
- **Специалист** использует упрощённый сценарий, исправляет собственные записи за любые месяцы, получает личный отчёт и Excel.

Дубли проверяются отдельно по видам работы `expert` и `specialist`. Одинаковый номер в разных видах работы не считается дублем.

## 3. Файл сверки

- Администратор загружает один `.xlsx` с колонками `Заказ` и `Поставщик`.
- Каждая загрузка хранится как отдельная версия с датой, автором, именем, SHA-256 и строками файла.
- Активна только одна версия. Новый файл включается атомарно после полной проверки; ошибочная загрузка не отключает предыдущую.
- Номера нормализуются: внешние пробелы удаляются, латиница переводится в верхний регистр, числовые Excel-ячейки читаются без научной записи.
- Одинаковые пары объединяются. Разные поставщики у одного номера отклоняют весь файл. Пустой поставщик допускается с предупреждением.
- Поставщик сохраняется снимком у каждого номера заказа. Последующие загрузки не меняют старые записи. При исправлении номера сверка выполняется заново.
- Если файл отсутствует или номер в нём не найден, бот не разрешает продолжить ввод этого заказа.

Исторический справочник поставщиков физически сохраняется для совместимости и отката, но ручной ввод, модерация, активация и выбор поставщика убраны из интерфейса.

## 4. Проекты

- `Тандер, АГРОКОНТАРКТ/МАФ`
- `Тандер, арбузы`
- `Тандер, САМОВЫВОЗ`
- `Х5 САМОВЫВОЗ`
- `Х5 ТЕХМП RVI`

Проекты и сценарии имеют внутренние неизменяемые коды. Исторические проекты переименовываются и объединяются миграцией без удаления инспекций.

## 5. Сценарий специалиста

Порядок: дата → номер → дубль → статус → дополнительные заказы → проект → ставка → комментарий → подтверждение.

- Обычная запись: `далее` или `отгружены в одну авто`.
- Для одной машины обязательно от 2 до 10 заказов; каждый номер сверяется отдельно.
- При дубле доступны только комиссионная или повторная инспекция. Проект берётся из самой ранней специалистской записи этого номера.

## 6. Сценарий эксперта

Порядок: дата → проект → номер → дубль → статус → дополнительные данные → ставка → комментарий → подтверждение.

- `Тандер, САМОВЫВОЗ`, `Тандер, АГРОКОНТАРКТ/МАФ`, `Х5 ТЕХМП RVI`: осмотр/стоп-отгрузка, одна машина, холостой выезд, далее. Выбор `далее` выгружается как `контроль отгрузки`.
- `Х5 САМОВЫВОЗ`: контроль отгрузки, смена, одна машина, холостой выезд; для одной машины обязателен номер автомобиля.
- `Тандер, арбузы`: смена или далее.
- При дубле сохраняется проект, выбранный в начале, и доступны комиссионная или повторная инспекция.

## 7. Корректировки и аудит

- Сотрудник редактирует собственные записи за любой период.
- Администратор редактирует запись любого сотрудника.
- Сотрудник может удалить собственную запись, администратор — запись любого сотрудника. Удаление восстанавливаемое: запись скрывается из рабочих списков, отчётов и выгрузок, а снимок сохраняется в истории.
- Перед каждым изменением сохраняются дата, все номера и поставщики, проект, статус, сценарий, автомобиль, ставка и комментарий.
- Изменённая после выгрузки инспекция снова считается невыгруженной.
- Старые callback-кнопки поставщиков показывают понятное сообщение об изменившемся сценарии.

## 8. Excel и отчёты

- Книга содержит вкладки `Специалисты` и `Эксперты` с одинаковыми 12 столбцами.
- Каждый номер заказа занимает отдельную строку.
- Номер группы, сотрудник, дата и проект повторяются на строках одной инспекции.
- В первой строке находятся статус, ставка и комментарий.
- В дополнительных строках статус `-`, ставка — числовой `0,00`.
- Даты добавления и изменения, а также статус обработки повторяются на каждой строке одной инспекции.
- Для одной машины проекта `Х5 САМОВЫВОЗ` номер автомобиля добавляется к статусу первой строки.
- Одна инспекция, машина или смена считается одной выполненной единицей независимо от числа заказов.
- Дубли подсвечиваются отдельно для экспертских и специалистских записей.
- Состояние обработки и повтор неудачной выгрузки сохраняются на уровне всей инспекции.

## 9. Критерии готовности

- Миграция сохраняет исторические инспекции, поставщиков и проекты.
- Проходят Ruff, полный pytest, PostgreSQL-миграционный тест, проверка блокировки дублей и Redis FSM.
- Excel проверяется программно и визуально: две ролевые вкладки, фильтры, текстовые номера, числовая ставка `0,00`, корректная построчная структура.
- Перед переносом на рабочий сервер отдельно создаются и проверяются резервные копии приложения и PostgreSQL.
